# Exit-parameter calibration: break_even_trigger_pct / max_hold_days

Historical, walk-forward calibration of the two exit-intelligence parameters left as explicit judgment calls in the earlier trailing-stop/correlation calibration pass. **Read-only**: this document is evidence for a decision, not the decision itself -- no `tradepulse/` risk-profile value changes with this pass; applying any recommendation below is a separate, later, explicitly-approved step.

## Methodology

- **Deterministic-layer only, not a full production backtest.** Entries are generated by the same fixed-baseline `compute_real_factors`/`weighted_composite`/`signal_from_composite` pipeline production actually runs (regime-conditioned weights were reverted ahead of this pass) -- **no AI-recommendation gate is simulated**. Historical AI opinions can't be reconstructed; this validates the deterministic layer, not "what production would have done."
- **Same-symbol re-entry matches production, verified from source**: `execution/gateway.py`/`scanner/coordinator.py` have no check blocking a BUY candidate for an already-held symbol -- only in-flight *unresolved* orders are blocked. So every BUY/STRONG_BUY signal is treated as an independent hypothetical entry, matching production's real pyramiding behavior, not a simplification. Consecutive-day signals on the same symbol are still highly correlated observations, not independent samples -- every table below reports unique-symbol/unique-date counts alongside raw trade counts.
- **Data**: fetched via the account's own `AlpacaClient` (same IEX feed the live paper account uses). Equity universe coverage: 2020-07-27 -> 2026-09-03 (~1,500-1,536 bars/symbol, 0 gaps >5 calendar days). Crypto: 2021-01-01 -> 2026-09-04 (~2,044-2,073 bars/symbol for BTC/ETH/LTC/BCH, 0 gaps; SOL/USD has 2 gaps >2 days and shorter coverage -- a genuine, isolated data-completeness issue, not generalized to the rest of the crypto universe).
- **Gap/fill rule**: if a day's open is already at/through the operative stop, the exit fills at that open (a real gap-through is never assumed to fill at the stale stop price); otherwise, if the day's low touches the stop, the exit fills AT the stop (the standard daily-bar intraday-touch approximation).
- **Benchmark alignment is by date, not array position** -- the relative-strength benchmark slice at day D is every benchmark bar dated <= D, an as-of lookup, never a same-length positional slice.
- **Walk-forward folds, common calendar boundaries across every symbol** (not a per-symbol ratio split, which would train/test different symbols on different calendar eras when pooled):

  - fold_1: Train <=2022-12-31, Test 2023
  - fold_2: Train <=2023-12-31, Test 2024
  - fold_3: Train <=2024-12-31, Test 2025
  - fold_4: Train <=2025-08-31, Test 2025-09+

- **Friction, frozen before any result was examined**: equity 0/5/15 bps-per-side (gross/base/stress), crypto 0/10/30 bps-per-side (wider, reflecting real spread/venue-fee differences). Every result reported under all three -- a result that only survives Gross is labeled as such.
- `trailing_atr_multiplier` held fixed at balanced's already-calibrated value (2.5) throughout -- this pass tests break_even_trigger_pct/max_hold_days only.

## Recommendation: break_even_trigger_pct / max_hold_days

**No combination in the grid shows robust positive expectancy** -- every equity fold's train sensitivity grid is negative in every cell (base friction), across all 8 max_hold_days values and all 6 break_even_trigger_pct values; the "best" combination in each fold is the least-negative cell, not a genuinely profitable one. Crypto is similarly negative in three of four folds; the one exception (fold_2's out-of-sample test, +0.35R base friction) comes from 17 trades across 3 symbols and 14 unique dates -- too thin and too concentrated to trust as a real edge rather than noise (see the independence caveat in the methodology section).

**Recommendation: keep the current per-profile judgment-call values** (aggressive 6%/10d, balanced 4%/15d, conservative 2.5%/30d, micro 3%/12d) -- per the acceptance rule established before this pass began, a result search that finds no robust improvement over the existing values should not force a change onto them. Nothing in this grid beats the current values by a margin that survives friction and out-of-sample testing.

**This is very likely not primarily an exit-parameter problem.** The negative expectancy shows up *regardless* of which break_even_trigger_pct/max_hold_days combination is chosen, which points at the entries themselves, not the exit tuning. This is exactly corroborated by the separate crypto-signal-sparsity diagnostic below (§ Finding: crypto fixed-composite signal sparsity, part 4a): composite scores in the 65+ BUY zone show *negative* forward expectancy for **both** equity (-0.009R at 65-69, -0.124R at 70+) and crypto (-0.219R at 65-69), while the 45-59 zone shows the *best* forward expectancy for both classes. The exit-parameter grid's entries are drawn exclusively from that same underperforming 65+ zone (`signal_from_composite`'s BUY threshold), so no amount of exit-parameter tuning can fix an entry-signal-quality problem. If this is pursued further, the more consequential lever is very likely the deterministic entry signal itself, not `break_even_trigger_pct`/`max_hold_days` -- a separate, future, properly-scoped investigation, not something to act on from this pass alone.

**The permanent limitation stated once more, because it matters most here**: this entire calibration -- the grid above and the sparsity diagnostic below -- tests the **deterministic layer in isolation**, with no AI-recommendation gate simulated (historical AI opinions can't be reconstructed). If the AI gate is doing real, valuable filtering work in production -- rejecting deterministic BUY signals that don't actually have good setups -- then production's real, combined AI+deterministic pipeline could perform meaningfully differently than what's measured here. This backtest cannot rule that out, and this document does not claim it can. It's real evidence about the deterministic layer, not a verdict on production performance.

## Finding: crypto fixed-composite signal sparsity

Discovered while reviewing the exit-parameter calibration's entry counts: BCH/USD's composite score crossed the production BUY threshold (>65) exactly once across 2,044 gap-free days of history. This section is a **separate, read-only diagnostic** -- it does not calibrate or change `break_even_trigger_pct`/`max_hold_days` (that's the section above), and it changes no production weight, threshold, or factor formula. It only produces evidence for a later, separately-approved decision.

**Grounding fact**: under the current fixed baseline weights (`default_strategy_weights()`), `liquidity_weight`/`risk_quality_weight`/`relative_strength_weight` are all zero -- `weighted_composite`'s renormalization excludes a zero-weight factor entirely. So today, only **technical_score/momentum_score/risk_score** (weights 25/15/15) actually drive the live composite; the other three factors are computed but currently inert.

Per-symbol evidence confirms this is a volatility effect, not an asset-class label: TSLA (equity, high realized volatility) has a median composite of 47.1 -- indistinguishable from crypto -- while SHY (equity, a low-volatility bond ETF) has the highest median of any universe symbol (63.3) and by far the most BUY signals (34.3% of days). `risk_score` is functioning as a realized-volatility detector that happens to disadvantage crypto systematically, since crypto is structurally higher-volatility than nearly every equity in the universe -- not something that inspects asset class directly.

### Classification: B + C, with one caveat and one finding beyond original scope

**C is well-supported**: `risk_score` accounts for essentially the entire composite gap between equity and crypto (an ~11.7-point weighted contribution gap against an ~11.7-point observed composite median gap), and per-symbol evidence confirms it's tracking realized volatility, not asset class directly (TSLA, a high-volatility equity, scores as low as crypto; SHY, a low-volatility bond ETF, scores highest of any universe symbol and generates the most BUY signals by far). Critically, `risk_score`'s own within-crypto predictive discrimination (§4c) is noisy and non-monotonic -- the most volatility-penalized crypto bucket (<20) shows 5-day forward returns (+0.89%) comparable to or better than several higher buckets (40-59: +0.10%, 80+: +0.24%). That's the direct evidence for C: the factor depresses crypto's composite without reliably identifying worse subsequent crypto outcomes.

**B is also supported, but not as a crypto-exclusive finding**: crypto's 45-49 composite bucket shows better hypothetical-long-outcome expectancy (+0.15R) and better pure forward return (+2.2% at 5 days) than its 65-69 bucket (-0.22R, -1.1%) -- consistent with B, that the universal 65 threshold is excluding better-performing crypto observations than it's admitting. **The same declining-with-composite pattern appears in equity** (peak expectancy at 50-59, declining to -0.009R at 65-69 and -0.124R at 70+) -- so this isn't a crypto-specific miscalibration relative to a well-calibrated equity threshold; the same pattern is present in both. That's a more significant and more general finding than the original crypto-sparsity question was scoped to catch, and it's the same pattern the exit-parameter grid above independently corroborates (universally negative expectancy in the 65+-sourced entry set, for both asset classes) -- worth treating as its own follow-up question about the deterministic composite/threshold design generally, not folded into a crypto-only fix.

**Confidence caveat**: the crypto evidence weakens at the high-composite end specifically -- the 65-69 bucket has only 79 crypto samples (5 symbols), and 70+ has only 2. The overall *direction* (declining expectancy with composite) is consistent across two independent methodologies (4a, exit-policy-dependent; 4b, exit-policy-independent) and across both asset classes, which is real corroboration -- but the crypto tail-bucket numbers themselves should be read as directionally consistent, not precisely estimated.

**No production change follows from this pass.** If pursued, the recommended next step is a separate, properly-scoped, held-out-validated investigation into the composite/threshold design itself (not a crypto-specific patch) -- mirroring the same walk-forward discipline used for the exit-parameter calibration above, given the pattern appears to span both asset classes rather than being a crypto-only defect. The previously-reverted regime-conditioned placeholder weights are not a candidate fix for this -- they were reverted for being unvalidated, and nothing in this diagnostic validates them.
