# DBAE Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every new Alpaca entry passes a balance-aware policy that does all of the following, without ever changing the operator's risk profile:
- unlocks asset classes by verified session equity;
- verifies account and asset capabilities;
- reserves funding for unfilled buys across symbols;
- rounds quantities down to what the broker supports;
- refuses entries whose protective exit isn't proven.

**Architecture:**
- **Policy:** a pure policy package, `tradepulse/dbae/`, holding the bands, policy, evidence table and baseline.
- **Capability reads:** separate capability protocols in `tradepulse/broker/capabilities.py`. `BrokerPort` is unchanged.
- **Gateway:** one integration point in `ExecutionGateway.execute_intent`, inside the existing `_portfolio_risk_lock`.
- **Monitor:** uses the policy's scale-out feasibility check.
- **Verification:** freezes DBAE's policy into each generation.

**Tech Stack:** Python 3.12, Decimal arithmetic, asyncio, SQLite via `PersistenceRepositories`, pytest with `respx`, mypy (`check_untyped_defs`), Ruff.

**Spec:** `docs/superpowers/specs/2026-10-30-dbae-design.md` (rev. 4, main `28642c7a`). Section references (§) below point there.

## Global Constraints

- Build in a worktree (`superpowers:using-git-worktrees`), on branch `dbae`. Never edit `tradepulse/` in the main checkout during a soak or verification run.
- No production broker orders, no paper orders, and no IBKR calls. Every test uses the simulated broker or `respx` mocks.
- Fix at the core: no `# type: ignore`, no `cast`, no `assert` used for narrowing, and no loosened checks. Narrow with explicit branches and named refusals.
- Money is `Decimal`. Never use floats. Parse every broker numeric through the existing `decimal_value`/finite checks. A non-finite or unparsable value becomes `None` (unknown).
- Capability fields are `T | None`, and `None` means unknown. Unknown never grants permission (§3.2).
- `contract_multiplier` always comes from `contract_multiplier_of(asset)` (`tradepulse/models/market.py:62`). `account_multiplier` is used only in §5.3's account-type check (§7.2).
- Band thresholds: `20`, `50`, `100`, `500`, `2000`, inclusive at the lower edge (§4.1).
- `DBAE_EVIDENCE_MAX_AGE_SECONDS = 30`, `dbae_policy_version = "dbae-1"`, required options level `2`, accepted `account_multiplier` ∈ {2, 4}.
- The refusal reason strings are exactly those in spec §10, plus `DBAE_QUANTITY_IDENTITY_MISMATCH` and `generation_predates_dbae`.
- Commits are GPG-signed (`git commit -S`), and each ends with the `Co-Authored-By` trailer. Never bypass signing.
- Every task ends with these passing: `.venv/bin/pytest -q`, `.venv/bin/mypy` (zero errors over the package) and `.venv/bin/ruff check` (no new findings).

## Reviewer conditions (plan review, 2026-10-31)

- **Execution method.** Subagent-driven: a fresh implementer and an independent reviewer for each task.
  - The reviewer may reject a task and return it to the implementer.
  - One integration owner (the controlling session) keeps the Interfaces blocks of Tasks 4–7 fixed. A change to any of them is made in this plan first, before a subagent uses it.
- **Evidence report per task.** Each task ends with:
  - the files changed;
  - the exact test commands and their outcomes;
  - the invariants checked;
  - unresolved findings;
  - the signed commit SHA.

  A passing suite alone does not accept a task.
- **DBAE-P1: fenced authorization.** The fence already exists. The portfolio-risk lock's `owner_token` is checked by `_check_lease` (`persistence/repositories.py:79`) inside the `RISK_APPROVED` write's own `BEGIN IMMEDIATE` transaction, and an expired or taken-over lease raises `RepositoryLeaseLostError` with nothing written. DBAE must keep every reservation-bearing write on that fenced path. Task 7 adds the stale-worker test, and the static check in Task 5 is extended to it.
- **DBAE-P2: funding conservation across a crash.** For any state, `funding_available ≤ verified_capacity − P`, where `P` counts only unfilled, unattributed obligations. Task 7 adds the crash/restart integration test through the real gateway.
- **DBAE-P3: no partial activation.** Everything stays on the `dbae` branch in its worktree. Nothing is merged, deployed or frozen into a generation until Task 10's gates pass and the operator approves separately. Task 9's `generation_predates_dbae` makes partial activation inside an existing generation impossible regardless.

## Review Focus

1. **Empty-string and null numerics from Alpaca.** Fields such as `non_marginable_buying_power: ""`, `options_trading_level: null` or `"NaN"` must parse to `None` and refuse only the dependent class. Pinned in Task 2.
2. **Scientific-notation increments.** A `min_trade_increment` of `"1e-9"` or `"0.000000001"` must floor identically, with no float rounding. Pinned in Task 3.
3. **Evidence stamped in the future.** A `received_at` more than 5 s after `now` (clock skew) is treated as unverified, not as fresh. Pinned in Task 2.
4. **Lease lost between shaping and the `RISK_APPROVED` write.** No intent is approved, no reservation appears, and the result is the existing lease-lost refusal. Pinned in Task 7.
5. **The second `evaluate_risk` run must use the same quote and snapshot as the first.** A quote that moves between the runs must not change the outcome. Pinned in Task 7.
